## Proposals (ranked)

### 1. The production origin serves `/metrics` and `/health/*` to anyone, unauthenticated

- **Evidence.** From this VM, with no credential of any kind:
  `curl https://api.roomy.space/metrics` returns **4,129 lines** of Prometheus
  text — per-endpoint request counters for every XRPC route, the query-cache
  internals (`roomy_cache_hits_total`, per-NSID hit/miss/eviction),
  `roomy_db_open_space_dbs{worker="space-0"…}` each at **100**,
  `roomy_db_space_cache_kib`, pool worker backlogs, embed/search/push backlog
  gauges. `curl https://api.roomy.space/health/pool` returns the pool's worker
  count, per-worker open-DB counts and ceilings; `/health/push` returns the
  dispatcher's lifetime delivery counters; `/health/cache` returns the cache
  hit/miss/eviction table by NSID. No auth is applied to any of them: the
  handler is `packages/appserver/src/appserver.ts:1272` (`if (url.pathname ===
  "/metrics")`, reached from the main `fetch` handler with no check ahead of
  it), and `/metrics` is a literal in the endpoint-label table at
  `appserver.ts:600`. Nothing in the repo gates it: `grep -r ROOMY_INTERNAL_SECRET
  packages/appserver/src` returns nothing, while the Rust worker does gate its
  internal surface with exactly that variable
  (`crates/roomy-appserver/src/main.rs:208`). The scrape does not need the
  public route — the collector is configured against the private address
  (`deploy/alloy/config.alloy:19-26`, `APPSERVER_METRICS_URL =
  appserver.railway.internal:8080`).
- **Why now.** The last four daily records each list "the appserver's live
  `/health` and `/metrics`" among their inputs, i.e. the surface has been used
  unauthenticated for a week without anyone noting that it needs no credential;
  it was being treated as a read-only probe rather than as public. What it
  discloses is the
  server's internal topology and capacity headroom (open space DBs, pool
  ceilings, cache sizes, per-route traffic), plus an unauthenticated path that
  drives `poolStats()` and a full render on every request. The exposure is not
  a compromise, it is an unintended public surface — and the codebase already
  has the convention for the alternative.
- **Scope sketch.** Decide the surface: gate `/metrics` and `/health/*` behind a
  token (a `ROOMY_METRICS_TOKEN` checked in the same handler, or the existing
  `ROOMY_INTERNAL_SECRET` convention), or serve them only on a listener bound
  to the deployment's private network. Keep `/health` itself public if the
  platform's health check uses it. Do not change what the collector scrapes.
- **Acceptance.** An unauthenticated `GET /metrics` from a host outside the
  deployment returns 401 or 404, while the Alloy scrape still succeeds and
  Mimir's `up{job="prometheus.scrape.appserver"}` stays 1 for 24 h.
- **Suggested priority:** **P3**.
- **Not already tracked because.** No task names it and no scout record has
  raised it; the closest precedent (`TASK-449`, `#580` — attribute a 401 to the
  caller) is about naming callers of XRPC routes, not about which routes should
  be public.
