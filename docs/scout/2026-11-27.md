## Considered and rejected

- **A proposal to instrument the hourly freeze.** `#625` is that instrument
  (event-loop lag histogram, per-worker stall counters), `#630` is the tick's
  timer, `#632` is the index under it. Proposing a fourth would add a queue
  entry to a 37-PR review backlog for work already written and green. The
  finding goes in the queue audit as an ordering argument instead.
- **A proposal to bound the maintenance tick's work.** Plausible next step if
  `#630` shows the tick is the stall, but proposing a redesign before the
  timing exists would be guessing at the mechanism the scout could not observe.
- **A proposal for the 22.1 s `getMetadata`.** Its own statements are in the
  same `HH:28` window as six other days' stalls; TASK-498 bounds the sweep, and
  a per-request deadline would hide the stall rather than remove it.
- **A proposal for the 8,031 ms rotation query.** One occurrence, inside the
  stall, on a table with four figures of rows: the query is the victim, not the
  cause. TASK-498 already bounds the page query beside it.
- **A proposal for the 5,526 401s.** TASK-19's baseline, ninth day; its
  re-measure condition is under-specified, not unmet (queue audit), and today's
  new fact — the limiter fires for a client that reports — belongs there.
- **A proposal to make the storm client reload onto the current bundle.**
  Unchanged from yesterday: a stale bundle cannot be distinguished from a fetch
  path the session-health wrapper does not see, and eviction code would live in
  a bundle the storm client is not running. The measurement that separates them
  is CF13/CF14 landing.
- **A proposal to deploy.** The single largest fix available today is a deploy
  of `a81e00c9`; that is Meri's action and CF27, not a worker task.
- **A proposal for the projection rebuild (97 / 35.8 s).** `#623` is that
  subject, open and green.
- **A proposal for the read-state purges.** `#632` indexes them; today they are
  the statements inside the freeze window, which is `#630`'s measurement.
- **A proposal for `space-2`'s 83.6 s of `db-slow`.** The largest worker share
  again, no single statement over 200 ms in its top runs, and the statement
  timing that would explain it is `#598` (merged, undeployed).
- **A proposal for the 05:37Z fan-out (`getSpaces` across nine workers).** Real
  and reproducible in shape, but `getSpaces` p95 is 62 ms over 220 requests: the
  fan-out is only expensive when the process is already stalled, which is
  headline 2.
- **A proposal for the 864 member-count failures.** CF4/`#510`, and the log
  line that would name the status is what `#590`/TASK-455 adds — a PR that now
  needs re-iding before it can merge.
- **A proposal for the 121 ingest skips.** TASK-479 and `#622` give the payload
  shape a counter; the count moves with traffic (109 → 137 → 121).
- **A proposal for the 9 × `Failed to record scope grant` / `Failed to fetch
  profile`.** Every one is a consequence of a session already declared expired
  in the same second; the cause is TASK-19's, not a separate defect in the
  scope-grant path.

  the field still accepts an email address, and the count is 3 in 24 h.
