## Considered and rejected

- **A proposal to make the storm client reload onto the current bundle.**
  Headline 3 shows the client that needs the fix is not running it, and a
  version check plus reload would bound future stale tabs. Rejected for this
  tick because the mechanism is unproven: a stale bundle cannot be distinguished
  from a fetch path the `session-health` wrapper does not see, and the eviction
  code would live in a bundle the current storm client is not running. The
  measurement that would separate them is CF13/CF14 landing; the proposal should
  be written once that has a number behind it, not before.
- **A proposal for the 5,444 401s themselves.** TASK-19's baseline, eighth day,
  and the re-measure condition is now demonstrably under-specified rather than
  merely unmet (queue audit). It goes there, not here.
- **A proposal for the `session-health` limiter's run reaching 26.** 38 samples
  across three users, one run resetting after the limit; whether the hand-off
  reached the login path is still the missing datum and is the same subject as
  the storm.
- **A proposal to deploy.** The single largest fix available today is a deploy
  of `a81e00c9`; that is Meri's action and CF27, not a worker task.
- **A proposal for the projection rebuild's 123 slow runs.** `#623` is that
  subject, open and green.
- **A proposal for the 15,335 ms `SWEEP_SQL`.** TASK-498 bounds the statement;
  today's figure is its worst case, not a new cause.
- **A proposal for the room-page select (211 / 54.3 s).** No run crossed 1 s; the
  aggregate is the cost of 211 routine pages, and `getMessages` p95 since boot is
  under 1 s over 48,310 requests.
- **A proposal for the cross-worker 11:28Z cluster.** Recorded as a log finding;
  its two candidate instruments (`#630` tick timing, TASK-498 sweep deadline) are
  both already in review.
- **A proposal for `space-2`'s 5.4 ms mean query wait.** Real and named by an
  exported histogram, but the statement timing that would explain it is `#598`
  (merged, undeployed) and the worker has no user-visible failure attached.
- **A proposal for the 795 member-count failures.** CF4/`#510`, and the log line
  that would name the status is what `#590`/TASK-455 adds.
- **A proposal for the 137 ingest skips.** TASK-479 and `#622` give the payload
  shape a counter; the count moves with traffic (109 → 105 → 98 → 137).
- **A proposal for the two Roomy→Discord forward failures.** 4 in 7 days, both
  for the same message at 22:14Z, with the underlying "Failed to send request to
  discord"; too rare to scope without the status that `#590` would add.
- **A proposal for the profile-chunk timeouts.** 3 lines inside 4 minutes, each
  falling back to Bluesky; the refusal-shaped gap is TASK-497 and its credential
  half needs HappyView admin access no worker has.
- **A proposal for the APNs null-status retries.** One device, 5 attempts in
  24 h, retried with backoff, and `apn.ts` drops the broken session so the next
  attempt redials.
- **A proposal for the 14.4 % poor navigations.** The sample is 521 across
  browsers and devices, the tail is one 29.6 s navigation, and nothing consumes
  the rating until `#554` gives it a chart (CF30).
- **A proposal for `roomy_readstate_watermarks_unresolved` 162.** The module
  documents it as a property of the data, re-derived every boot by design, with
  `repaired_total` 0 because the boot repair found nothing to re-anchor.
- **A proposal for the 15 (guild, space) pairs failing open on capacity.**
  `capacity.ts:346` emits that summary at most hourly by design, the transition
  lines fired zero times in 24 h, and the fix is provisioning bridge-token
  grants — an operator action, not code. TASK-380/`#498` is the capacity work
  already in review.
- **A proposal for `/health/push`'s 17,430 / 172 ratio.** Not a delivery
  failure: `dispatched` counts jobs evaluated (`push/dispatcher.ts:285`), and
  most evaluations produce no delivery because no recipient has a subscription.
- **A proposal for the Mimir series.** CF26: the series alternates between
  production and staging. Everything quoted above from `/metrics` came from a
  single `api.roomy.space` request.
- **A proposal from `#meta`.** Nothing new since 2026-10-22T00:17:38Z; the
  standing thoughts there (concurrency cap, merge plan, self-improvement loop)
  are TASK-142 and CF33, and the carried-forward pile is recorded against
  TASK-142 in the queue audit rather than as its own task.
- **A proposal for `#554`'s Netlify checks.** CF18; the checks fail on every PR
  opened since 2026-10-28 and are not this PR's business.
